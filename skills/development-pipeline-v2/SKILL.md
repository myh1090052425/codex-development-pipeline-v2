# Development Pipeline v2

## Scope And Roles

- Run only after the user explicitly invokes `$development-pipeline-v2`. One run has the current main session, one frozen task, and one normalized Git or Non-Git root; do not infer continuation from another task.
- The current main is the sole Coordinator. It reads and freezes evidence, dispatches direct custom-role agents, waits, verifies release, applies gates, and reports. It never writes candidate code, tests, or fixes and never applies a writer's patch.
- Use only direct agents named `dp-v2-implementer`, `dp-v2-verifier`, and `dp-v2-reviewer`; they never delegate. Never use `create_thread`, `fork_thread`, or `send_message_to_thread` as a lane.
- One invocation authorizes the complete local, reversible Design/TDD/FULL/Review/fix loop inside the same scope and architecture; do not ask per round. Ask only for material scope/architecture expansion or production, external, credential, permission, destructive, data, Git history, or Git index risk. Otherwise narrow safely or return `BLOCKED`.
- The Implementer is the sole logical writer and at most one writer is active; Reviewer is logically no-write and Verifier writes only frozen scratch/output. TOML sandbox values are requested defaults, not proof of effective permissions. This runtime never modifies its Skill, agents, configuration, or v1.

## Preflight And Snapshot

- Read applicable `AGENTS.md`, Git status and recent commits, relevant implementation/tests/dependencies/config, and dirty paths. Reuse in this order: existing implementation, existing dependency, stdlib/platform, then the smallest justified addition.
- Resolve one root by `realpath`. Git starts with a sanitized environment that removes `GIT_DIR`, `GIT_WORK_TREE`, and `GIT_INDEX_FILE` and fixes `LC_ALL=C`, `GIT_OPTIONAL_LOCKS=0`; require `git rev-parse --show-toplevel` and an existing `HEAD`. Non-Git root must be explicit. Block on escape, nested repo, submodule, unsafe symlink, special file, or mismatched writable root.
- Before dispatch freeze scope, architecture, batch, write/test/input/output boundaries, cleanup, dirty paths, commands/env/order/dependencies, prohibited actions, deadline/poll, and parent plus child actual effective sandbox/permission profiles. Every role payload carries `effective_confinement=HARD|AUDITED_FULL_ACCESS`.
- HARD requires evidence that the child Reviewer is actually read-only and Implementer/Verifier are exact-root workspace-write; only then call confinement platform-enforced. AUDITED_FULL_ACCESS is allowed only when the user explicitly selected Full access in the parent turn, work remains local/reversible, and no check needs hard isolation.
- Under AUDITED_FULL_ACCESS, keep logical role boundaries; redirect HOME/TMP/cache/bytecode and command outputs to predeclared root scratch, freeze root/protected hashes and full tree manifests, ban external/credential/production/Git-risk actions, and report residual risk exactly: boundary is not OS-enforced and zero writes outside root cannot be proven. A hard-required check is `BLOCKED(capability-unavailable)`.
- The literal Git snapshot profile contains root realpath and `HEAD`; raw NUL `git status --porcelain=v1 -z --untracked-files=all`; raw NUL `git ls-files --stage -z`; raw binary `git diff --binary --no-ext-diff --no-textconv --no-renames HEAD`; raw NUL `git ls-files --unmerged --stage -z`; scoped `git --literal-pathspecs ls-files -v -z -- <declared paths>`; and each declared path's absence/type/mode/content hash/symlink target.
- From scoped `-v`, freeze only assume-unchanged and skip-worktree semantics. Ignore fsmonitor-valid as a mutable cache bit and do not add `-f`. Detect merge, cherry-pick, revert, rebase, sequencer, and bisect state; snapshot every detected state path and directory descendant with absence/type/mode/content hash/symlink target. Any change is drift; never restore Git operation files automatically. Block unless resolving that operation is authorized.
- Each role rejects an incomplete profile. For every actual writable root, take ordered pre/post tree manifests covering tracked/untracked/ignored paths with path/type/mode/hash/symlink; AUDITED also rechecks protected hashes. If full observation is infeasible, use a disposable copy or return `BLOCKED`; an allowlist is not a Full access platform boundary. Freeze scratch preimage/restore.
- Coordinator commands are snapshot-only; it never reruns tests/builds. A workspace-write Verifier's pre/post evidence proves only no persistent delta, never no transient write. A check needing strong zero-write must use actual hard read-only plus scratch or a disposable copy.
- Every Verifier command records ordinal, argv, cwd/env, start/end snapshot, exit/signal, stdout/stderr raw or SHA plus byte count, dependency skip, outputs, cleanup, and daemon/delayed-child teardown. Missing, stale, reordered, wrong-scope, undeclared-output, unauthorized-drift, or failed-cleanup evidence is `BLOCKED`; do not clean it and continue.

## Worker Lifecycle

- Before the run, prove the main can directly spawn all three custom roles, observe real status, close/interrupt, obtain `not_found` from a later wait/status, and spawn again after release. If not, return `BLOCKED(capability-unavailable)`; never invent a token or handle.
- Before spawn, freeze the literal payload, allocate a never-used run-local opaque payload_id, and verify it is present/unreused and its map entry matches payload, role, mode, root, write_set, and other bindings. Only then spawn and bind handle+expected ID; failure means zero dispatch and `BLOCKED`. Do not serialize, hash, or persist this map.
- A role only requires one nonempty internally consistent payload_id and echoes it unchanged; it does not know map uniqueness or reuse. Missing/multiple/conflicting ID may return pre-execution BLOCKED, and a missing-ID final may omit echo. Coordinator treats final echo != handle expected ID as terminal identity `BLOCKED`, not crash: no replacement, stop dispatch, check drift, and release. Only a matching echo proceeds to ordinary status/evidence checks. Legal first lines remain Implementer `PASS|BLOCKED`, Verifier `PASS|FAIL_CANDIDATE|BLOCKED`, Reviewer `PASS|VALID_FINDINGS|BLOCKED`; other missing/illegal final is crash and malformed finding is `BLOCKED`.
- After terminal, close/release and prove a later wait/status is `not_found` before a dependent dispatch. Unproven release is `BLOCKED(unreleased-agent)`. A crash may be replaced once only after release, zero unauthorized delta, and zero residue; writer delta or a second crash is `BLOCKED`.
- Capacity error is not crash or cycle. If run-owned agents remain active, keep work pending and retry only on a real release event. If none are active, or retry after the last release still fails, return `BLOCKED(capacity-unavailable)`. Never busy-loop or close an external handle.
- Poll timeout only schedules another observation. Deadline expiry is a preauthorized cancel: stop new dispatch, interrupt/close that handle, then return `BLOCKED(deadline-exceeded)` if released or the higher-priority `BLOCKED(unreleased-agent)` if release cannot be proved.
- Dynamically parallelize independent read-only lanes within actual capacity. Never overlap candidate writers; serialize Verifier commands that write scratch/output. On cancellation or run-level `BLOCKED`, stop dispatch and release every run-owned handle.

## Design And Effective Findings

- Use Design only for high risk or materially different solutions. When freezing each complete design, Coordinator assigns a stable run-local design_id plus line/section anchors, binds them to its design cycle, and supplies them to every DESIGN payload without persistence or hashing. Fresh lanes review the same design and anchors over scope, architecture, data/error boundaries, verification, reuse, and risks. Maximum three designs.
- Reviewer `VALID_FINDINGS` is raw input. Coordinator independently replays each well-formed finding's trigger/evidence and clear condition. Reproducibly refuted items leave the effective set; if all are refuted, the lane is effective PASS and creates no repair or cycle. Malformed result/finding is `BLOCKED`.
- Only the complete effective P0-P3 set may produce the next design or candidate repair batch. A third design with an effective finding terminates `DESIGN_NOT_ACCEPTED`; all effective lanes PASS freezes the accepted design.

## TDD And Candidate Cycles

- Before mutation, dispatch a fresh Verifier in `BASELINE` mode for every executable clear check on one snapshot. Classify PASS with no skip/xfail as `already-satisfied`, and target-caused failure as `requires-change`; wrong reason, weak/unexecuted check, or environment error is `BLOCKED`.
- If all items are already satisfied and no persistent test is requested, freeze that snapshot as the `candidate_cycle=none` review target with zero writers and empty changed paths. Complete FULL plus effective Review PASS accepts directly; only FULL `FAIL_CANDIDATE` or a nonempty effective finding set creates repair, whose first cycle-forming writer forms cycle 1.
- Every Implementer payload has `phase=test-preparation|cycle-forming` and `cycle_effect=NONE|FORM_CANDIDATE`. Valid pairs are RED test-preparation/NONE; mixed CHARACTERIZE test-preparation/NONE; standalone or characterization-repair CHARACTERIZE cycle-forming/FORM_CANDIDATE; GREEN/FIX cycle-forming/FORM_CANDIDATE. One writer means concurrent exclusivity, not one Implementer total per batch.
- In mixed work, finish all requires-change RED and already-satisfied persistent-coverage CHARACTERIZE test preparation sequentially with cycle_effect=NONE, then freeze all tests; only the GREEN/FIX production delta forms one cycle. Reuse strong RED targets or add one minimal test-only batch, verify every target is executed/unskipped and fails for the frozen reason, and allow at most three complete preparations.
- CHARACTERIZE covers only satisfied behavior. FULL proves real-candidate PASS and frozen negative-fixture/disposable-counterfactual target-caused FAIL with no persistent candidate/input delta and complete cleanup. If unsafe, irrelevant, or unreplayable, return `BLOCKED`. After counterfactual/FULL failure, a characterization repair may change only those characterization test paths, preserve every RED target, leave production unchanged, and form the next cycle.
- GREEN/FIX preserve frozen tests and make one minimal production delta. Every writer follows its phase/effect pair and requires a nonempty stable attributable delta.
- Only a FORM_CANDIDATE writer with terminal PASS, release, and stable post snapshot/tree manifest atomically forms/increments cycle 1/2/3 before FULL. NONE, crash, `BLOCKED`, empty, or unattributable delta does not. FULL failure or effective finding consumes that cycle.
- FULL uses a fresh Verifier on one stable snapshot: all regression obligations, frozen RED targets, characterization evidence, affected tests, static/type/build, and required runtime checks. Dependency skips name the root failure and unexecuted commands. PASS also requires no persistent candidate/input delta, restored outputs, and daemon teardown.
- After FULL PASS, run fresh CANDIDATE reviewers over correctness/scope/error/data flow, TDD/regression, repository consistency, reuse/maintainability/anti-overdesign, plus evidence-selected security, API, migration, performance, frontend, UX, accessibility, or other applicable dimensions.
- For a legal no-cycle or cycle 1/2 failure batch, repeat BASELINE, required preparation, one FORM_CANDIDATE writer, FULL, and all Review. After cycle 3 fails or retains effective findings, drain and terminate `CANDIDATE_NOT_ACCEPTED`; prohibit the next FORM_CANDIDATE GREEN/FIX/CHARACTERIZE. Preparation writers do not count toward this guard.

## Review And Terminal Results

- Reviewer mode is exactly `DESIGN|CANDIDATE`. DESIGN needs frozen design/scope/acceptance/dimensions but no candidate or Verify. CANDIDATE needs target snapshot, changed paths, assigned dimensions, and bound FULL PASS.
- Every raw finding has ID, P0-P3, dimension, trigger/evidence, impact, constrained fix, and executable clear condition. CANDIDATE location is repo `path:line`; DESIGN must use the payload's `design_id:line` or `design_id:section` anchor unchanged. Style, LOC, preference, speculation, and coverage gaps are not findings. Reviewer reports raw findings; Coordinator owns effective validation.
- Accept only when FULL PASS, every applicable lane is effective PASS, effective P0-P3 is empty, snapshots are stable, outputs restored, and all handles released. Terminal outcomes are `ACCEPT`, `DESIGN_NOT_ACCEPTED`, `CANDIDATE_NOT_ACCEPTED`, or `BLOCKED(reason)`.
- Report root/scope, final snapshot, changed paths, ordered command evidence, FULL/Review outcomes, cleared findings, release results, residual risks, and actions not performed. Do not persist run bookkeeping or continue automatically after terminal.
